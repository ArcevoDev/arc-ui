# Auth Components Guide

The `@arcevo/facet-auth` package provides a complete authentication system built on `@arcevo/facet-sdk`.

## ArcProvider

Wrap your app with `ArcProvider` and pass an `ArcIdClient` instance:

```tsx
import { ArcProvider } from "@arcevo/facet-auth";
import { ArcIdClient } from "@arcevo/facet-sdk";

const client = new ArcIdClient({
  baseUrl: "https://auth.arcevo.dev/api/v1",
});

function Root({ children }) {
  return <ArcProvider client={client}>{children}</ArcProvider>;
}
```

`ArcProvider` handles:
- Session restore from stored tokens
- Automatic access token refresh
- Login, registration, logout
- MFA flow coordination

## SignIn

Multi-step sign-in with a state machine:

```tsx
import { SignIn } from "@arcevo/facet-auth";

<SignIn
  config={fintechPreset}
  onSuccess={(tokenPair) => console.log("Logged in", tokenPair)}
/>
```

Steps: `idle → select_method → login_form → check_mfa → mfa_challenge → complete`

## SignUp

Registration with validation:

```tsx
import { SignUp } from "@arcevo/facet-auth";

<SignUp onSuccess={(tokenPair) => console.log("Registered", tokenPair)} />
```

## Guard

Route protection component:

```tsx
<Guard role="admin" fallback={<Unauthorized />}>
  <AdminPanel />
</Guard>
```

## UserButton

User menu with avatar, name, organization switcher, and logout:

```tsx
<UserButton />
```

## Customizing Components

Every auth component is dynamically configurable by consumers through
three prop families: `appearance`, `slots`, and `config`.

### appearance (styling)

Pass className overrides to the root element (or specific slots where
supported):

```tsx
<SignIn
  appearance={{ className: "max-w-md rounded-3xl border-primary/20" }}
/>
```

### slots (content replacement)

Replace built-in copy or nodes with your own. Available slots vary by
component (title, description, footer, trigger, complete):

```tsx
<SignIn
  slots={{
    title: <h1>Welcome back</h1>,
    description: <p>Sign in to your workspace</p>,
    complete: <RedirectToDashboard />,
  }}
/>
```

### config (behavior)

Pass a partial `AuthConfig` to override domain presets per-instance:

```tsx
<SignIn
  config={{ requireMfa: true, allowMagicLink: false, oauthProviders: ["google"] }}
  onOAuth={(provider) => window.location.assign(`/oauth/${provider}`)}
/>
```

The same pattern applies to `SignUp`, `Guard`, `UserButton`, `MfaDialog`,
and every standalone form (`LoginForm`, `MagicLinkForm`, `MfaVerifyForm`,
and the rest). Because `config` is `Partial<AuthConfig>`, any consumer
can build their own presets from an existing one and pass them per
component:

```tsx
const myPreset = { ...defaultPreset, sessionTtl: 60, oauthProviders: ["google"] };

<SignIn config={myPreset} />
```

## MfaDialog

MFA verification dialog with OTP input and recovery codes:

```tsx
<MfaDialog
  open={showMfa}
  client={arcIdClient}
  sessionId="sess_xxx"
  onComplete={(result) => handleLogin(result)}
/>
```
